2026-10-14 - Diagnostic tracing added for the confidence-50/off-topic bug and the 100s+ latency (Claude Code). Diagnosis only, from reading code — nothing run against the live server, no numbers measured this session:
  - Confidence (lexai_engine.py query(), the `confidence` field and the gate's `best`): both come from the exact same variable, `best = ranked[0]["score"] if ranked else 0.0`, where `ranked[0]["score"]` is set in `_rerank()` as `c["score"] = _sigmoid(float(logit))` on the top reranked chunk. `confidence = round(best * 100)`. There is no separate blend, clamp, or default path that produces 50 specifically — the only fallback is `best = 0.0` when `ranked` is empty, which would show confidence 0, not 50. So a confidence of exactly 50 on an off-topic query means the reranker's raw logit for the top (still irrelevant) chunk was close to 0, since sigmoid(0) = 0.5. Read from code only — not yet confirmed by printing the raw logit for the actual off-topic query from the 2026-10-13 smoke test; the new debug block's `reranker.top5_raw_logits` will show this on the next run.
  - Gate (`if best < CONF_THRESHOLD`, CONF_THRESHOLD = 0.30 from .env): compares that same `best` value, so the number shown as confidence and the number the gate checks are identical — there is no discrepancy between "what's displayed" and "what's gated." The gate not refusing at confidence 50 is simply 0.50 >= 0.30: the threshold did its job on the number it was given, the number itself was just too high for an off-topic query. Why the reranker scores an off-topic query's best chunk at ~0.5 instead of lower is unverified from code alone (model behavior, not a logic bug in this file as currently read).
  - LLM calls per /query, in call order, all via `_ask_llm` (max_tokens=2048 each, no retry logic anywhere in this file): lookup path = `_condense` (skipped entirely, 0 calls, if `self.history[owner_id]` is empty — i.e. first turn) -> `_generate` (always 1 call) -> `_verify` (always 1 call, wrapped in try/except that returns `True` on failure but does not retry). So 2 calls on a first turn, 3 on a follow-up turn. Meta path (`_is_meta` true) makes exactly 1 call, via `_meta_answer` -> `_generate`, skipping condense/retrieval/verify entirely. Nothing in this file retries an LLM call; the 100s+ latency reported 2026-10-13 was described there as cold-start model loading, not multiple calls — the new debug block's per-call `duration_ms` list will show whether that holds for a real query.
